# Development planning artifacts

These are human-authored planning documents for future AI-DLC adoption. They are **not** generated AI-DLC runtime state, an installed methodology, or evidence of completed lifecycle stages.

| Artifact | Purpose |
| --- | --- |
| [Planning state](planning-state.md) | Current scope, progress, and next work |
| [Intent](inception/intent.md) | Build objective and scope boundary |
| [Requirements](inception/requirements.md) | Stable requirement IDs and acceptance intent |
| [Backlog](inception/backlog.md) | User stories and proposed dependency order |
| [Traceability](inception/traceability.md) | Requirements linked to design and evaluation |
| [Construction](construction/README.md) | Future working-slice entry criteria |
| [Operations](operations/README.md) | Deferred runtime planning |

The local `inception/` folder groups planning inputs for convenience; it is not an assertion that upstream Ideation has passed or that AI-DLC uses this directory layout. Once adopted, let the selected release create its own state and artifact paths. Link or migrate reviewed inputs deliberately; do not fabricate historical audit events.

See the [AI-DLC adoption plan](../workflows/development/ai-dlc-adoption.md).
