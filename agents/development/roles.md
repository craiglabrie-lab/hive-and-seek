# Development role map

Status: planning roles, not configured or running agents. Names below describe project responsibilities, not an installed AI-DLC configuration.

| Responsibility | Project outputs | Boundary |
| --- | --- | --- |
| Product / discovery | Intent, scope, requirements, user stories, acceptance criteria | Separate product assumptions from user-confirmed goals |
| Architecture / ontology | Domain model, interfaces, permissions, ADRs | No unreviewed technology commitment |
| Delivery / coordination | Units of work, dependencies, plan, progress | Do not claim completion from a template |
| Implementation | Future smallest working slice | Only after implementation authorization |
| Quality / critical review | Evidence review, scenario design, actual check results | Independent review where tooling supports it; label simulation |
| Security / privacy | Data boundaries, tool permissions, retention, threat analysis | No private candidate corpus in engineering records |
| Operations | Future observability, recovery, budget, deployment plan | No deployment or cloud resources in this scaffold |

Use AI-DLC's actual agent/stage definitions when a release and harness are selected. Do not rename these documents into engine configuration and assume they will execute.

The development orchestrator manages engineering work; the career orchestrator serves a job seeker. Their state, credentials, permissions, and audit records must remain separate.
