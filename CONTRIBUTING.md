# Contributing

Begin with the [project overview](README.md) and [planning state](aidlc-docs/planning-state.md). The repository is currently a design foundation.

1. Link each change to a requirement, open question, or documented problem.
2. Keep one authoritative artifact for each concern; link to it from summaries.
3. Mark new design choices as proposed until the owner accepts them. An illustrative example is not an accepted user preference.
4. Record consequential architecture choices using the [decision template](templates/decision-record.md).
5. Check relative links, requirement references, agent boundaries, and privacy before committing.
6. Describe what changed and what was actually verified. Do not mark runtime scenarios passed without executing them.

Only synthetic career examples belong here. Private records and their summaries, embeddings, exports, and logs must remain outside the public repository. Ignore rules are a convenience, not access control.

No project license has been selected. Do not copy third-party source, prompts, figures, or documentation without checking their terms and retaining required notices. AI-DLC references currently link upstream; no upstream runtime is vendored.
