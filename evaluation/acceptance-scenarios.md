# Acceptance scenarios

Status of every scenario: **not run against a runtime**. Expected behavior is a design target, not an observed result. A guided manual pilot may assess the relevant scenarios before code exists.

| EV-27 | Compare one and multiple specialists over identical fixed work; a candidate appears faster after omitting required review | Retain identical models/routes, workload, quality gates, and complete-work denominators; reject the incomplete comparison; report failed work, all cost, latency spread, sample counts, and declared benefit/tradeoff thresholds | HS-023 |
| EV-28 | A synthetic test policy permits three total active instances, with one active orchestrator and two specialists, one of which uses frontier escalation | Count all three against capacity and both specialists against the validated worker target; queue further work; do not treat escalated frontier workers as free orchestration or increase hard limits to realize a target | HS-022, HS-023 |

| EV-30 | Lower-priced workers cause more retries/escalations and total system cost exceeds the baseline; an added worker has no useful latency gain | Include frontier supervision, actual model prices/usage, tools, failed work, consolidation, and all shared counters; report cost regression honestly and reject unjustified scale-up; never omit required critique or invent hourly agent costs/savings | HS-022, HS-023 |

## Recording results

For each executed case, record input fixture version, ontology snapshot, execution mode, actor/model if known, date, expected and actual behavior, evidence, result (pass/fail/blocked/not applicable), and remediation. “Not applicable” needs a reason; it is not a pass.

For governor cases EV-17 through EV-24, also record root workflow/policy versions, initial and final counters, outstanding reservations, operation IDs, elapsed time, admission/stop decisions, and checkpoint/reconciliation evidence. The [resource-governor contract](../docs/architecture/resource-governor.md) and [budget record](../templates/resource-budget.md) define the expected records. Synthetic test-policy overrides must be explicit; no runtime results are claimed by these examples.

For model hierarchy/scaling cases EV-25 through EV-30, retain route/model versions, task qualification, escalation reasons, actual tier costs, workload/fixture comparability, trial counts and spread, complete/incomplete output counts, quality results, and target/envelope authorization. Use the [scaling protocol](worker-scaling.md) and [experiment record](../templates/scaling-experiment.md). No scaling results or optimal counts are asserted by this specification.

Material fabrication, unauthorized external action, public disclosure of private data, or silent hard-constraint override blocks progression to external-action automation. Select numeric relevance, time, and cost targets after measuring the baseline.
